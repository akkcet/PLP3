# Biovia Pipeline Pilot (PLP) to Python Refactoring Suite

An enterprise-grade refactoring suite and interactive transpiler workbench that converts Dassault Systèmes Biovia Pipeline Pilot (PLP) protocols into clean, modular, testable Python 3.11+ automation services for Electronic Lab Notebook (Biovia Notebook) and Azure Storage integrations.

---

## 1. Executive Logic & Architecture Overview

The legacy Biovia Pipeline Pilot protocol (`Data model UI`, format 8.0.0) orchestrates automated ingestion of scientific data files generated by instruments or analytical models into Biovia Notebook (ELN):

1. **Gatekeeping & State Transition**: Evaluates PilotScript conditions (`@experiment_number`, `@xml`, `@filelist`) to validate execution phases.
2. **Metadata Ingestion**: Parses model export XML to extract generic data tags, file references, and storage folder hierarchies (`users/...`).
3. **Data Staging (Azure File Share)**: Downloads approved files from Azure SMB storage (`ShareServiceClient`) to local staging.
4. **Section Dispatching**: Inspects file extensions and attaches them to target Biovia Notebook experiments:
   - `.pdf` $\rightarrow$ PDF Section with page preview
   - `.xlsx` / `.xls` $\rightarrow$ Excel Table Section with row/column preview
   - `.ppt` / `.pptx` $\rightarrow$ PowerPoint Presentation Section
   - `.docx` / `.doc` $\rightarrow$ Word Document Section
   - Other extensions $\rightarrow$ Generic File Attachment Section
5. **Notebook Persistence & Cleanup**: Commits changes via Biovia Notebook REST API and purges temporary files.

## 3. Agentic Threat Model (The 5 Threat Zones)

| Threat Zone | Scenario | Potential Risk | Architectural Countermeasure |
|---|---|---|---|
| **1. Input Surfaces** | Untrusted Model XML Upload | XXE injection or Billion Laughs denial-of-service | Replaced standard XML parser with `defusedxml.ElementTree`; entities and DTD parsing disabled; 15MB payload cap. |
| **1. Input Surfaces** | Malicious ELN value paths | Path traversal via `../` in file basenames | Sanitized with `Path(eln_val).name` and boundary checked against ephemeral staging directory. |
| **2. Planning & Reasoning** | Dynamic PilotScript Injection | Arbitrary code execution via `eval()` | Dedicated lexer and token whitelist parser. Never invokes `eval()` or `exec()` on raw strings. |
| **3. Tool Execution** | Unbounded `Delete File` Action | Accidental deletion of operational system files | Bound strictly to `tempfile.TemporaryDirectory()` subpaths; denies relative escapes. |
| **4. Memory & State** | Cross-tenant file collisions | Shared static download path leaking data between experiments | Isolated ephemeral temporary directory per execution with guaranteed `ExitStack` teardown. |
| **4. Memory & State** | Credential leakage in logs | Session tokens or Azure keys printed to stdout | Log filter redacting `Authorization`, `X-Biovia-Session-Token`, and `account_key`. |
| **5. Inter-System** | Cleartext Azure Key in legacy PLP | Key compromise from exported protocol XML | Removed plaintext credentials; requires runtime injection via Secret Manager or `AZURE_STORAGE_KEY`. |
| **5. Inter-System** | Insecure REST calls | Man-in-the-Middle eavesdropping | Enforced TLS/HTTPS with `verify=True` across all HTTP endpoints. |

## 4. Google Cloud Run Deployment & Configuration

### Prerequisites
1. Install [Google Cloud SDK](https://cloud.google.com/sdk/docs/install) (`gcloud`).
2. Enable required Google Cloud APIs:
   ```bash
   gcloud services enable run.googleapis.com secretmanager.googleapis.com firestore.googleapis.com
   ```

### Secret Manager Configuration
Store the Gemini API Key and Azure Storage credentials in Secret Manager:
```bash
# 1. Create Secrets
gcloud secrets create GEMINI_API_KEY --replication-policy="automatic"
echo -n "YOUR_GEMINI_API_KEY" | gcloud secrets versions add GEMINI_API_KEY --data-file=-

gcloud secrets create AZURE_STORAGE_KEY --replication-policy="automatic"
echo -n "YOUR_AZURE_STORAGE_KEY" | gcloud secrets versions add AZURE_STORAGE_KEY --data-file=-

# 2. Grant Cloud Run Service Account Secret Accessor Role
PROJECT_NUMBER=$(gcloud projects describe $(gcloud config get-value project) --format="value(projectNumber)")

gcloud secrets add-iam-policy-binding GEMINI_API_KEY \
  --member="serviceAccount:${PROJECT_NUMBER}-compute@developer.gserviceaccount.com" \
  --role="roles/secretmanager.secretAccessor"

gcloud secrets add-iam-policy-binding AZURE_STORAGE_KEY \
  --member="serviceAccount:${PROJECT_NUMBER}-compute@developer.gserviceaccount.com" \
  --role="roles/secretmanager.secretAccessor"
```

### Cloud Firestore Security Rules (`firestore.rules`)
```javascript
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /users/{userId}/interactions/{interactionId} {
      allow read, write: if request.auth != null && request.auth.uid == userId;
    }
  }
}
```

### Cloud Run Deployment Command
```bash
gcloud run deploy biovia-plp-converter \
  --source . \
  --platform managed \
  --region us-central1 \
  --allow-unauthenticated \
  --set-secrets="GEMINI_API_KEY=GEMINI_API_KEY:latest,AZURE_STORAGE_KEY=AZURE_STORAGE_KEY:latest" \
  --set-env-vars="NODE_ENV=production,AZURE_STORAGE_ACCOUNT=bnlwestges01005,AZURE_SHARE_NAME=rdplp-sbx1"
```

### Mandatory Verification Binding
